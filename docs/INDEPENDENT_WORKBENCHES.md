# Independent Workbench Architecture

David-OS GUIs are independent workbenches, not panels in one required monolith.
Each workbench must launch on its own, own no canonical truth, and exchange data
through versioned SQLite/CSV/JSON receipts.

## Implemented

### Term Closure Planner

- Launcher: `python scripts/term_closure.py`
- Purpose: scan one or more selected roots for a configurable topic and its
  synonyms, group exact SHA-256 content, propose one keeper, represent other
  locations as duplicate pointers, and propose `GOLD_1` through `GOLD_4` bands.
- Naming boundary: gold bands describe proposed document relevance/quality;
  they do not replace the existing Theophysics epistemic `L1-L4` field and do
  not admit anything to canon.
- Mutation boundary: observe/propose only. Gathering, quarantine, and deletion
  must be separate approval-backed operations with hash verification and receipts.

Example:

```powershell
python scripts/term_closure.py --topic "Master Equation" `
  --term "master-equation" --term "master_eq" `
  --root "C:\theophysics\OPUS\Master Equation" `
  --output "runs\master-equation-closure"
```

### Master Equation Intake Workbench

- Launcher: `gui/START_MASTER_EQUATION_INTAKE.bat`
- Engine: `engine/master_equation_intake.py`
- Purpose: corpus map, SHA-256 content objects, location-preserving exact duplicate
  families, source lanes, document roles, ten-variable coverage, conservative
  contamination review, and scan-error visibility.
- Mutation boundary: writes only to a selected output folder; never changes the
  selected source corpus.

### FileTagger

- Launcher: `gui/START_FILETAGGER_GUI.bat`
- Purpose: lightweight sampled catalog and basic tags.
- Current limitation: legacy MD5 catalog and shallow three-tag model. It should
  remain a quick cataloger rather than becoming the canon or lineage workbench.

### FIS Scanner

- Launcher: `python gui/fis_scanner_gui.py`
- Purpose: richer multi-tag scan and aggregate SQLite browsing.
- Current limitations: content-hash primary keys collapse duplicate locations;
  displayed FIS-page links are not generated by this scanner; PySide6 is required.

## Next independent workbenches

1. **Duplicate Review** — reads `content_objects` and `file_instances`; compares
   duplicate families and near-duplicate candidates. It proposes no deletion.
2. **Lineage Workbench** — shows source lane, timestamps, hashes, and document
   relationships; it never selects canon automatically.
3. **Canon Review** — displays Candidate, Admitted, historical, superseded,
   contradiction, and unresolved states; every ruling requires a receipt.
4. **Tagging Workbench** — edits proposed tags/classifications separately from
   file identity and provenance.
5. **Corpus Search** — searches all receipts and extracted text without owning
   moves, renames, or canon decisions.

## Shared contract

- File instance identity is path-specific.
- Content identity is SHA-256-specific.
- Duplicate content never erases provenance-bearing locations.
- `UNKNOWN` and unresolved values remain visible.
- Candidate is never silently promoted to Admitted.
- Observe and propose are default; approve is explicit and receipt-backed.
- Expansion/intake runs may grow the corpus. Compression is a later, separate,
  human-approved phase.


## Drive Harvester: guided scan and collection (2026-09-19)

Launch the existing `gui/START_DRIVE_HARVESTER.bat`. This extends
`gui/drive_harvester.py`; it does not introduce another program or launcher.

1. Enter a concept and optional synonyms. Choose Filename, Title / headings,
   File sidecar, Tags, and/or Document body. Sidecars include `.sidecar.json`,
   `.fmeta`, and `.chi`; tags include frontmatter and inline hashtags.
2. Check one drive or folder and scan. Pinned folders no longer expand the
   requested scope. The current text limit is 400,000 characters; files above
   25 MB are skipped. The result status identifies partial scans and access errors.
3. Select results. Review duplicates or empty items in the selected results,
   a chosen root folder and its descendants, or the whole drive used in the scan.
   Reviews inspect all file types when a folder/drive is selected. Protected
   system/cache directories and symlinks/junctions are skipped.
4. Review the findings. Duplicate review keeps a selected export copy and can
   exclude redundant selected copies. Empty review detects zero-byte files of
   any type, zero-visible-word text files, and directly empty directories.
   Findings do not delete or move sources. JSON reports can be saved explicitly.
5. Preview export destinations. Use an existing destination directly, optionally
   name a new collection folder, and choose flat, preserved subfolders, or
   grouping by extension. Export copies with exclusive creation, checksum
   verification, sidecars, original metadata text, and a timestamped CSV manifest.
   Stop cancels subsequent work and records unfinished exports; interrupted copies
   remain identified by attempted path in the manifest for review.

Search, review, and export run in background threads. The existing
`engine.symptoms.content` duplicate detector accepts an existing inventory and
hashes only groups with equal file sizes; thin-content reading is bounded before
reading bytes. Folder/drive reviews cover accessible paths only. This prototype
uses bounded text extraction and does not yet offer an incremental content cache,
semantic duplicate merging, or source deletion/moving. Relative document links
are not rewritten during export; flattening can therefore break relative links.
